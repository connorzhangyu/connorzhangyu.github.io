Go学习计划

🏁 阶段一：语言基础（Week 1~2）

🎯 目标

掌握 Go 的语法结构、数据类型、控制流、函数机制。

✅ 学习内容

  • 基本语法、变量、常量、数组、切片、map
  • 控制结构（if, for, switch）
  • 函数与多返回值、defer
  • 指针（区别于 Java 的核心知识点）
  • 结构体与方法

📚 推荐资料

  • Tour of Go（交互式）
  • Go by Example
  • 李文周基础语法章节（可作为中文参考）

🚀 阶段二：并发与标准库（Week 3~4）

🎯 目标

理解 Go 的并发模型，熟悉关键标准库。

✅ 学习内容

  • Goroutine、Channel、select
  • 错误处理（error 接口、errors 包）
  • 文件操作、时间处理、字符串处理、JSON 编解码
  • 单元测试、基准测试

📚 推荐资料

  • 《Go语言101》并发章节
  • Learn Go with Tests
  • Go.dev 文档：net/http、time、io

🧱 阶段三：现代开发工具与依赖管理（Week 5）

🎯 目标

熟练掌握项目结构、模块化、依赖管理。

✅ 学习内容

  • Go Modules（go.mod、go.sum）
  • 项目结构（cmd/pkg/internal）
  • 日志库（zap, zerolog）
  • 配置管理（viper）

🌐 阶段四：Web 开发实践（Week 6~7）

🎯 目标

掌握基于 Go 的 Web 服务开发

GitFlow分支规范

本规范适用于采用 Git Flow 模式进行项目开发的团队，以确保开发流程有序、版本可控、协作高效。

分支结构

项目将使用以下主要分支：

  • master：主分支，部署到生产环境的稳定版本。
  • develop：开发分支，集成所有功能分支的代码。
  • feature/*：功能分支，从 develop 分出，用于开发新功能。
  • release/*：发布分支，从 develop 分出，用于准备发布版本。
  • hotfix/*：热修复分支，从 master 分出，用于修复生产环境的紧急问题。
  • test：测试环境分支，用于部署测试环境，通常基于 develop 或 release/*。

分支命名规范

  • 功能分支：feature/功能名称
  • 发布分支：release/版本号
  • 热修复分支：hotfix/修复描述
  • 测试分支：固定为 test

工作流程

  1. 开发新功能：从 develop 拉取 feature/* 分支进行开发。
  2. 合并功能：开发完成后合并到 develop，并删除 feature/* 分支。
  3. 准备发布：从 develop 创建 release/* 分支，修复 bug、准备文档。
  4. 发布上线：release/* 测试通过后合并到 master 和 develop。
  5. 紧急修复：从 master 创建 hotfix/*，修复完成后合并到 master 和 develop。
  6. 测试环境部署：将 develop 或 release/* 合并到 test，供测试人员验收。

标签规范

每次发布到 master 的版本应打标签，格式如下：

v1.0.0
v1.0.1

提交规范

建议使用以下格式的提交信息：

类型: 简要描述

详细描述（可选）

常用类型包括：feat、fix、docs、style、refactor、test、chore。
