《TOSA · 后端技术规范与架构规划》⌗

版本号：v1.0 发布日期：2025-08-14 作者：Connor 适用范围：TOSA所有后端服务（Go 技术栈） 状态：正式发布 目标：统一后端技术栈、指导新项目从 MVP 到企业级最佳实践的迭代路径，降低维护成本、提升交付质量。

后端架构迭代规划⌗

v0.1 – Foundation（最小基础架构）⌗

目标：单体可运行，具备基础可观测性与可迁移性

  • 中间件：请求日志、Recover、Request-ID、超时（context）
  • 交付物：最小 CRUD（用户/任务）、/healthz、/readyz
  • 退出标准：
    • golangci-lint 通过
    • go test -race 通过
    • 容器可启动
    • 数据库迁移可回滚

v1.0 – MVP 上线（必须功能）⌗

目标：可对外服务的最小生产版本

  • 新增：
    • go-redis（cache-aside）
    • JWT
    • swaggo/swag（OpenAPI）
    • 限流（令牌桶 / 滑动窗口）
  • 设计：错误码统一、分页 Keyset 优先、幂等键（Idempotency-Key）
  • 观测：Prom 指标（RED：Rate / Errors / Duration）、基础 Grafana 看板、告警（CPU/内存/错误率/P95）
  • CI/CD：GitHub Actions（lint → test → build → 镜像 → 部署）、Artifact 归档
  • 环境：Staging + Prod，配置分层（dev/stage/prod）
  • 退出标准：SLO（如 99.9% 可用、P95 < X ms）定义并可观测；报警通知链路有效

v1.5 – 稳定与扩展（数据一致性 + 任务）⌗

目标：稳态运行、容错与一致性保证

  • 一致性：Outbox + Relay（最终一致）、重复投递去重、消费者幂等
  • 任务：robfig/cron（周期）或 asynq（基于 Redis 的异步任务/重试/DLQ）
  • DB：pgBouncer（连接池）、备份 wal-g、读写分离（必要时）
  • 性能：热点缓存策略（TTL、版本号/ETag）、pprof、automaxprocs
  • 退出标准：灾备演练（备份 → 恢复）、核心流程重试/幂等验证通过、P95/错误率稳定达标

v2.0 – 微服务化（服务拆分 + 内网通信）⌗

目标：服务边界清晰，内外分离：外部 REST（Gin），内部 RPC（gRPC/Connect）

  • RPC：gRPC（内网/跨语言）或 Connect（兼容 HTTP/1.1/浏览器/网关更省心）
  • 接口治理：API 版本化（/v1）、兼容策略（proto 字段不复用 tag）
  • 弹性与容错：重试、熔断（gobreaker）、限流（服务级/用户级）
  • 日志/追踪：OpenTelemetry Trace 贯通（HTTP ⇄ RPC），统一 TraceID 写入日志
  • 网关（可选）：grpc-gateway / Connect 原生 HTTP 友好
  • 退出标准：跨服务 Trace 覆盖核心路径、蓝绿/金丝雀发布、零停机

v2.5 – 云原生生产（可伸缩与自动化）⌗

目标：可靠扩缩、自动化环境、强安全基线

  • 平台：Kubernetes（HPA、探针、滚动更新）、Terraform（VPC、DB、Cache、EKS）
  • 镜像与安全：多阶段构建、distroless、非 root、只读 FS、最小权限
  • 密钥：Secrets Manager / SSM / KMS；无明文落盘
  • 观测：OTel 指标+Trace 一揽子、DB/Redis Exporter、成本与容量看板
  • 退出标准：IaC 一键落环境、HPA 正常扩缩、基础安全扫描（SAST/govulncheck/SBOM+cosign）通过

v3.0 – 企业级最佳实践（合规 / 数据平台 / 多区域）⌗

目标：合规安全、审计、数据驱动、跨区域容灾

  • 安全与合规：SSO/OIDC、casbin（RBAC/ABAC）、审计日志、DLP、加密（传输+静态）
  • 数据平台：ClickHouse / Redshift / Athena，CDC/ETL（变更捕获）、主题数仓、报表
  • 发布：Argo Rollouts（金丝雀 / 蓝绿）、混沌演练（故障注入）
  • 运营：SLA 文档、Runbook、SLO/Error Budget 管理、FinOps（成本基线与优化）
  • 退出标准：合规审计通过、多区域灾备演练通过、SLO 达标与成本达标

3. 技术集成说明⌗

3.1 ORM 选型⌗

  • 长期维护/类型安全：sqlc（SQL 优先）或 Ent（Schema 优先）
  • 快速原型：GORM（可后续迁移）
  • 迁移策略：新模块新 ORM，旧模块渐进替换

3.2 RPC 选型⌗

  • 内网：gRPC（HTTP/2，高性能）
  • 对外/兼容：Connect（HTTP/1.1 友好）
  • IDL：统一用 Protobuf

3.3 数据库策略⌗

  • 起步：PostgreSQL + Redis（pgBouncer、wal-g）
  • 上云：Aurora PostgreSQL + ElastiCache
  • 分析：ClickHouse/Redshift 旁路分析

3.4 安全与合规⌗

  • Secrets 不落仓库，统一管理（AWS Secrets Manager/SSM）
  • JWT 短期会话，Refresh Token 长期
  • 依赖升级与漏洞扫描（govulncheck、Dependabot）

4. 附录：最佳实践守则⌗

  1. 中间件顺序：Request-ID → Recover → 访问日志 → 超时 → 限流
  2. 时间与主键：统一 UTC，主键用 ULID/KSUID
  3. 版本控制：语义化版本，变更日志（Keep a Changelog）
  4. 质量门槛：Lint、Race Test、Code Review、漏洞扫描必过
  5. 可观测性：RED 指标、Trace 全链路、日志统一字段（trace_id、req_id）
