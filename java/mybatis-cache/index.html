MyBatis 缓存机制详解：一级缓存、二级缓存与 PerpetualCache

MyBatis 缓存机制详解#

MyBatis 提供了两级缓存机制，用于减少数据库访问、提升性能。

🔹 一级缓存（Local Cache）#

  • 作用域：SqlSession 级别（默认开启）
  • 实现：基于 PerpetualCache 的 HashMap
  • 特性：
    • 在同一个 SqlSession 中，相同的 SQL 查询会直接命中缓存，不再发起数据库请求
    • 当执行 INSERT、UPDATE、DELETE 时，缓存会被清空（保证数据一致性）
    • 作用域小，线程隔离，安全可靠

⚠️ 注意：如果是不同的 SqlSession，即使 SQL 一样也不会共享一级缓存。

🔹 二级缓存（Mapper Cache）#

  • 作用域：Mapper 命名空间级别（需手动开启）
  • 实现：同样基于 PerpetualCache，可配置为 EhCache、Redis 等
  • 特性：
    • 在同一个 Mapper 下的不同 SqlSession 之间共享缓存
    • 生命周期更长，通常随应用进程而存在
    • 提高了缓存复用率，但要注意数据一致性问题

⚠️ 注意：二级缓存默认是关闭的，需要在 mybatis-config.xml 或 Mapper 文件中显式配置：

🔹 PerpetualCache • 定义：MyBatis 默认的缓存实现类，位于 org.apache.ibatis.cache.impl • 底层：本质是对 HashMap 的简单封装 • 特性： • 提供最基本的缓存操作：putObject、getObject、removeObject、clear • 通过装饰器模式与 LRU、FIFO、SoftReference、WeakReference 等策略结合使用 • 一级缓存、二级缓存都依赖它

⸻

🎯 总结 • 一级缓存：SqlSession 级别，默认开启，线程安全，生命周期短。 • 二级缓存：Mapper 命名空间级别，需手动开启，跨 SqlSession 共享。 • PerpetualCache：底层实现，简单 HashMap 封装，配合装饰器支持多种缓存策略。

✅ 开发中常见用法： • 读多写少 的数据（如字典表、配置表） → 建议开启二级缓存 • 高并发写入表 → 谨慎使用缓存，避免数据不一致
