MyBatis Plus + Spring Data JPA 分页架构方案#

在企业项目中，很多团队会选择 MyBatis Plus（MP） 与 Spring Data JPA 混合使用：

  • JPA 用于 简单业务表 的增删改查，快速开发。
  • MP 用于 复杂业务查询，需要自定义 SQL、灵活拼接条件的场景。

这种架构带来了分页问题：
两者的分页实现机制不同，需要统一和优化。

🔹 一、分页机制差异#

1. MyBatis Plus 分页#

  • 依赖插件：通过分页拦截器动态拼接 limit/offset。
  • 页码：从 1 开始。
  • 结果对象：IPage<T>。
  • 代码示例：
    1
2

    Page<User> page = new Page<>(1, 20);
IPage<User> result = userMapper.selectPage(page, new QueryWrapper<User>().eq("status", 1));

2. Spring Data JPA 分页#

  • 内置支持：无需插件，方法参数支持 Pageable。
  • 页码：从 0 开始。
  • 结果对象：Page<T> 或 Slice<T>。
  • 代码示例：
    1
2
3
4

    Page<User> findByStatus(Integer status, Pageable pageable);

Pageable pageable = PageRequest.of(0, 20, Sort.by("createdAt").descending());
Page<User> page = userRepo.findByStatus(1, pageable);

    // JPA 转换
public static <T> PageResult<T> fromJpa(Page<T> page) {
    PageResult<T> result = new PageResult<>();
    result.setRecords(page.getContent());
    result.setTotal(page.getTotalElements());
    result.setCurrent(page.getNumber() + 1);
    result.setSize(page.getSize());
    return result;
}

// MP 转换
public static <T> PageResult<T> fromMP(IPage<T> page) {
    PageResult<T> result = new PageResult<>();
    result.setRecords(page.getRecords());
    result.setTotal(page.getTotal());
    result.setCurrent((int) page.getCurrent());
    result.setSize((int) page.getSize());
    return result;
}

🔹 三、优化方案#

  1. 减少 Count 开销

    • JPA 默认会生成 count(*) SQL，可以通过 Slice<T> 避免。
    • MP 可在大数据量分页时自定义 Count 逻辑。

  2. 大分页优化

    1

    select * from user where id > ? order by id asc limit 20;

  3. 缓存策略

    • 高频查询分页结果可以做 Redis 缓存。
    • 分布式架构下需配合 分布式缓存 + 数据一致性策略。

🔹 四、面试题及答案#

1. 为什么 JPA 的分页页码是从 0 开始？#

答：因为 JPA 的 Pageable 接口设计时采用 数组下标思想，第一个元素索引是 0。

2. MyBatis Plus 的分页插件底层是怎么实现的？#

答：通过拦截器在执行 SQL 前动态拼接 limit/offset，并执行一次 count 查询计算总数。

3. 如何避免 JPA 自动生成的低效 count SQL？#

答：可以使用 @Query 手写 count 查询，或使用 Slice<T> 避免 count。

4. 什么时候选择 Page，什么时候选择 Slice？#

答：Page 适合需要总条数的分页场景；Slice 适合只关心是否有下一页的场景。

5. 如何优化 offset 很大的分页查询？#

答：改用 游标分页（keyset pagination），避免大 offset 扫描。

6. 分布式环境下如何保证分页数据一致性？#

答：需要 全局事务或分布式锁 保证一致性，缓存层用版本号或时间戳策略。

7. 你在项目里是如何统一 MP 和 JPA 的分页响应结构的？#

答：通过定义统一的 PageResult<T>，在适配层将两种分页对象转换成统一结构。

🎯 总结#

  • JPA：适合简单表，分页开箱即用，但 count SQL 需注意。
  • MyBatis Plus：适合复杂 SQL，自定义更灵活，但需要插件。
  • 架构最佳实践：定义统一的分页请求/响应 DTO，做一层适配，前端无感知。
